# Работа над Aegis

- Основная разработка — `develop`. Дополнительная ветка нужна только для
  изолированного эксперимента или параллельной работы; после слияния удаляется.
- `main` — проверенный снимок программы. Перенос из `develop` через pull request
  после успешных автоматических проверок и проверки заявленных возможностей.
- Коммит содержит осмысленное законченное изменение. Даты и результаты проверок
  настоящие. Не включать секреты, локальные настройки и собранные бинарные файлы.
- Ошибки возвращать с контекстом. Интерфейсы вводить со стороны потребителя
  при реальной необходимости. Горутины должны иметь путь завершения.
- Изменения поведения сопровождать тестами, исправления — воспроизведением ошибки.
- Для выпуска версии нужен тег на проверенном коммите `main`, затем Release.
  Не ставить тег стабильного выпуска на незавершённый этап разработки.

## Имена и обучение

Постоянных веток две: main и develop. Автоматические PR обновлений версий
отключены; обновления проверяем вручную в develop. При обоснованной необходимости
временная ветка получает короткое имя по задаче, например agent-metrics.
В объяснениях сначала определяем новый термин, затем показываем его на коде
Aegis, объясняем причины выбора и ограничения проверки.
