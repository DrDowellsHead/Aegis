# Установка и запуск

Первый этап предоставляет консольную программу, не графическое приложение.
Пока нет опубликованного релиза, можно собрать из исходников или получить
проверяемые архивы из артефакта CI `aegis-development-builds`.
Артефакты CI предназначены для разработки, не являются стабильным выпуском.

## Выбор архива

| Система | Имя в архиве | Процессор |
|---|---|---|
| Windows | windows_amd64 | Intel/AMD x64 |
| Windows on ARM | windows_arm64 | ARM64 |
| macOS Intel | darwin_amd64 | Intel |
| macOS Apple Silicon | darwin_arm64 | Apple M-series |
| Linux x86-64 | linux_amd64 | Intel/AMD x64 |
| Linux ARM64 | linux_arm64 | ARM64 |

Распакуйте архив. В терминале откройте полученную папку.
Windows PowerShell: `./aegis.exe version`.
Linux/macOS: `./aegis version`.
Go и Python на машине пользователя для запуска не нужны.

Архивы не подписаны сертификатом разработчика. macOS/Windows могут показывать
предупреждение о неизвестном издателе. Подпись и системные установщики — будущий
этап, а не уже реализованная функция. Не отключайте системную защиту целиком.

Проверьте SHA-256 скачанного архива по файлу SHA256SUMS:

- PowerShell: `Get-FileHash ./ИМЯ_АРХИВА.zip -Algorithm SHA256`.
- macOS: `shasum -a 256 ИМЯ_АРХИВА.tar.gz`.
- Linux: `sha256sum ИМЯ_АРХИВА.tar.gz`.

Контрольная сумма проверяет целостность, но не заменяет цифровую подпись.

## Пробный запуск

В первом терминале:

```sh
./aegis serve --listen 127.0.0.1:8080
```

Во втором:

```sh
./aegis check --url http://127.0.0.1:8080/healthz --timeout 3s
```

На Windows замените `./aegis` на `./aegis.exe`.
Завершение сервера — Ctrl+C. Администратор/root для этого не нужен.
`/healthz` показывает жизнь процесса, а не готовность БД или агентов.

Команда `check` выдаёт JSON. Код завершения 0 — HTTP 2xx; 1 — недоступность,
неподходящий HTTP-статус либо ошибка выполнения; 2 — ошибка аргументов.
Перенаправления не выполняются. Тело ответа не скачивается. Сертификаты TLS
проверяются. Системные HTTP-прокси не используются. Проверка однократная;
история и уведомления ещё не реализованы. Периодический сбор метрик ОС доступен через `agent`.

## Из исходников

Нужен Go 1.27.3 (версия CI; модуль требует Go 1.27 или новее).

```sh
git clone https://github.com/DrDowellsHead/Aegis.git
cd Aegis
git switch develop
go test ./...
go build -o bin/ ./cmd/aegis
```

`go test -race ./...` дополнительно проверяет гонки и требует подходящего
C-компилятора на машине разработчика; готовая программа от него не зависит.

Для сборки шести архивов разработчику нужны Go и Python 3:
`python scripts/package.py dev` (на Linux может потребоваться `python3`).
Повторный запуск не перезаписывает существующую папку `dist/dev`.

## Сбор показателей компьютера

```sh
./aegis collect --disk .
./aegis agent --disk . --interval 5s --count 3
```

На Windows: `./aegis.exe collect --disk C:\`.
Параметр `--disk` обозначает путь на измеряемой файловой системе, а не каталог,
размер которого требуется посчитать. По умолчанию используется текущий каталог.
Без `--count` агент работает до Ctrl+C. Данные выводятся локально, никуда не
отправляются и не сохраняются автоматически. Подробнее: [метрики](metrics.md).
