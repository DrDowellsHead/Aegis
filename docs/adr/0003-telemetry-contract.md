# ADR 0003: начальный контракт телеметрии

Статус: этап 3.1 (без сохранения и аутентификации).

## Решение

Unary gRPC + Protocol Buffers v3, протокол в api/proto, сгенерированный Go-код
в internal/telemetry/v1. Snapshot версии 1 сохраняет семантику локального
metrics.Snapshot: времена UTC, CPU, RAM, диск, сетевые счётчики и частичные ошибки.
network_available различает отсутствие группы и успешный пустой список.
measurement_id генерируется криптографически случайно для разового вызова.

Отдельные команды: receive (gRPC-приёмник), send (один замер и одна отправка).
Существующие serve/collect/agent не изменяют своего поведения.

## ВАЖНО: ограничения безопасности и надёжности

Без TLS и токенов приёмник и клиент принимают только числовые loopback-адреса
(127.0.0.1, ::1). Нельзя выставлять этот gRPC-порт в интернет.
agent_id пока не удостоверяет личность; он только текстовая метка.
Сервер проверяет формат и журналирует поступившее измерение, но не хранит его.

Успешный SendResponse.received означает «принято и проверено в памяти», а
НЕ «сохранено надёжно». Дубликаты не подавляются и повторная отправка не
реализована. При падении сервера полученное сообщение теряется.
Настоящий подтверждённый ACK, постоянный Agent ID, TLS/аутентификация,
дисковая очередь и повторные попытки относятся к последующим шагам.

## Команды

Терминал 1:
```sh
go run ./cmd/aegis receive
```

Терминал 2:
```sh
go run ./cmd/aegis send --server 127.0.0.1:9090 --agent-id local-demo --disk .
```

Формат protobuf генерируется командой bash scripts/generate-proto.sh после
установки protoc, protoc-gen-go и protoc-gen-go-grpc. Генерируемые файлы
фиксируются в репозитории для воспроизводимой сборки без protoc.
