# ADR 0007: HTTP API истории измерений

Статус: этап 3.5.

## Граница безопасности

Для чтения истории вводится отдельная команда `aegis history`, отделённая
от gRPC-сервиса `receive`. HTTP listener принимает **только числовой
loopback IP** (127.0.0.1 или ::1); внешняя публикация запрещена.
Оператор указывает отдельный `AEGIS_HISTORY_TOKEN` (32..4096 байт)
через переменную окружения. Это не токен агента. Токен передаётся по
Authorization: Bearer и сверяется по SHA-256 с constant-time сравнением.
HTTP-ответы содержат Cache-Control: no-store. HTTPS пока нет: API нельзя
публиковать за пределами доверенного локального хоста без отдельной
архитектуры аутентификации, TLS и разграничения доступа. Ограничение
loopback не является полноценной изоляцией от других локальных процессов.

Для уменьшения полномочий отдельный пользователь PostgreSQL с правом
SELECT (и без INSERT/UPDATE/DELETE) предпочтительнее подключения от
пользователя, которым сервер принимает измерения. API не создаёт
и не изменяет измерения.

## Контракт

GET /api/v1/measurements?agent_id=UUID&from=RFC3339&to=RFC3339&limit=50&cursor=...

- agent_id обязателен, UUIDv4 нижнего регистра.
- from включителен, to исключителен, оба необязательны.
- limit: по умолчанию 50, максимум 100.
- cursor: непрозрачный URL-safe base64 указатель, содержит (started_at,
  measurement_id) и привязку к agent_id/from/to, отклоняет другие фильтры.
- items — JSON с исходными Snapshot, включая null группы, пустую сеть
  и частичные ошибки. has_more и next_cursor позволяют читать следующие страницы.
- Неизвестные, повторяющиеся и некорректные параметры дают HTTP 400;
  отсутствие токена — 401; ошибка БД — 503.
- HTTP 405 возвращается для неверного метода.

## SQL и индексы

Вводится миграция 003: составной индекс
(agent_id, started_at DESC, measurement_id DESC).
SQL использует параметры ($1..$6), не конкатенацию пользовательских значений.
Выдача сортируется по двум столбцам; запрос следующей страницы использует
строгое сравнение tuple (started_at, measurement_id) < (cursor_time,cursor_id).
Выполняется `LIMIT (requested+1)` для определения наличия продолжения.
Клиент не получает ни SQL, ни секреты PostgreSQL, ни protobuf BYTEA.

API не гарантирует согласованный snapshot нескольких HTTP-запросов:
пока пользователь перелистывает страницы, могут приходить новые
измерения с историческим временем. Для неизменной выгрузки позже
понадобится watermark или отдельная модель чтения. OFFSET не используется.
Статистика и агрегация не входят в 3.5.

## Эксплуатация

Понадобится выполнить `aegis migrate` для индекса 003, после чего
`aegis history` откроет HTTP на 127.0.0.1:8081.
Существующие `serve`, `receive`, `send` и `forward` не меняют
свой публичный интерфейс. Таймауты HTTP и предел размера заголовков
снижают риск удержания соединений. API только читает PostgreSQL.
