# ADR 0008: числовые проекции и агрегирование временных рядов

Статус: этап 3.6.

## Проблема

PostgreSQL хранит полные измерения в Protobuf BYTEA. Для `AVG` и `MAX`
над CPU/RAM/диском их пришлось бы декодировать в Go и передавать каждую
строку по сети. Это не масштабируется с размером истории.

## Решение

Миграция 004 добавляет nullable CPU, memory, disk used percentages и disk_path,
а также флаг `projected`. Новые измерения вставляются атомарно с бинарным
снимком и числовыми проекциями. Отсутствующая группа остаётся SQL NULL;
успешно измеренный 0% сохраняется именно как ноль. Старые строки получают
projected=false и НЕ исчезают из исходного History API.

Команда `aegis backfill --batch-size 100` возобновляемо преобразует старые
protobuf BYTEA в числовые проекции. Каждая порция блокирует только выбранные
строки (`FOR UPDATE SKIP LOCKED`) и атомарно коммитится. При прерывании
можно запустить команду повторно; неудачная порция откатывается. Прогресс
не считается оконченным, пока нет ни одной строки projected=false.

SQL `date_bin` группирует строки по фиксированным UTC-интервалам
(1m/5m/15m/1h/6h/24h), вычисляет CPU avg/min/max, память avg и
диск avg. Диск считается только по явно выбранному disk_path, иначе
несопоставимые файловые системы могли бы случайно смешиваться.
Ответ сохраняет число снимков и количество доступных измерений каждой группы.
Отсутствующие группы представлены JSON null, пустые окна вообще
отсутствуют из списка (frontend показывает пропуски).

## API

GET /api/v1/series?agent_id=UUID&from=RFC3339&to=RFC3339&step=5m&disk_path=%2F

- локальный loopback API с отдельным AEGIS_HISTORY_TOKEN;
- только явно допустимые step, не больше 500 интервалов и 90 дней;
- границы [from,to), выравнивание bucket от Unix epoch в UTC;
- SQL не получает строки запроса через конкатенацию;
- HTTP 400 для плохих параметров, 401 для неверного токена;
- SQL агрегирует только projected=true; перед использованием старой
  истории оператор выполняет backfill.

## Ограничения и развитие

Пока не реализованы downsampling, materialized views, retention,
кэширование и агрегации сетевых скоростей: сетевые поля — накопительные
счётчики байтов, их нельзя усреднять как скорость передачи.
Схема БД и API должны развиваться вместе, через версионируемые миграции.
